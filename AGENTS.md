# Проект: Vigsharm — Интернет-витрина цветов / подарков (Армавир)

## Суть проекта
Локальный интернет-магазин/витрина для Армавира (+ радиус 50–100 км).
БЕЗ корзины и онлайн-эквайринга. Оформление происходит напрямую из карточки товара в мессенджеры или звонком.

## Главный пользовательский сценарий
1. Клиент заходит в каталог товаров.
2. Открывает карточку / модальное окно товара.
3. Выбирает:
   - Способ получения: Доставка (по Армавиру и до 100 км) или Самовывоз.
   - Дату и время (интервал).
   - При необходимости: текст открытки / пожелания к заказу.
4. Нажимает кнопку отправки заявки:
   - WhatsApp (генерируется готовый текст сообщения с названием товара, ценой, датой, временем и адресом/самовывозом).
   - Telegram (переход в чат или бот с готовым текстом).
   - Быстрый звонок на номер магазина.

## Стек и архитектура
- Быстрый, легковесный фронтенд (чистый HTML/CSS/JS или современный легковесный фреймворк без громоздкого бэкенда).
- Адаптивность: 80%+ заказов идет с мобильных телефонов (Mobile First!).
- Все токены стилей берутся строго из `DESIGN.md`.

## Правила для агента (Строгие запреты!)
1. НЕ предлагать и не внедрять корзину с оплатой картой на сайте. Заказ уходит в мессенджер.
2. НЕ менять дизайн-токены (цвета, шрифты) самовольно без разрешения.
3. Перед внесением крупных изменений ВСЕГДА сначала писать план шагов. Код писать только после утверждения.
4. Не создавать «типовой серый AI-дизайн» с фиолетовыми неоновыми кнопками.

## Локальный сервер для превью (важно!)
Для локального просмотра сайта используется кастомный скрипт `scripts/_dev_server_5500.py`
(не обычный `python -m http.server`!). Он умеет отдавать страницы без `.html`
(например `/catalog` → `catalog.html`), что важно для ссылок вида
`http://127.0.0.1:5500/?v=...#catalog`.

**Известная проблема:** если `_dev_server_5500.py` случайно удалён (например, при откате/уборке
временных скриптов) или порт 5500 занят обычным `python -m http.server`, то запросы без расширения
(`/catalog`, `/price` и т.д.) отдают 404 «File not found» (страница выглядит как стандартная
Python http.server 404), хотя сам сервер отвечает.

**Что делать:**
1. Проверить, что файл `scripts/_dev_server_5500.py` существует — если нет, восстановить его
   (см. историю чата/git) или создать заново по образцу ниже.
2. Запускать через скрипт, который убивает старые процессы на 5500 и поднимает один сервер:
   ```powershell
   cd C:\vigsharm-shop
   powershell -File scripts/start_dev_5500.ps1
   ```
   На Windows нельзя держать два слушателя на одном порту — браузер начнёт
   отдавать то старые, то новые файлы и «ронять» картинки.
   Dev-сервер: многопоточный keep-alive, gzip для HTML/CSS/JS, картинки кешируются,
   у CSS/JS в HTML — `?v=` от старта сервера (после перезапуска стили обновляются).
3. Если нужно вручную: `netstat -ano | findstr ":5500"`, затем
   `Stop-Process -Id <PID> -Force`, и только потом
   `python scripts/_dev_server_5500.py` (сервер сам откажется стартовать, если порт занят).
   НЕ `python -m http.server 5500` — он не поддерживает маршруты без `.html`.

**Как смотреть (проверено 2026-09-22):** запускать сервер в **своём** окне PowerShell
(админ ок), не фоном из чата Cursor — фоновые процессы часто обрываются и на :5500
остаются зомби. Смотреть в **Chrome/Edge**, не во встроенном Browser Cursor
(он зависает на белом экране и держит сокеты).

**Что ломалось и как чинили:**
- Два Python на :5500 (Windows SO_REUSEADDR) → то старый, то новый CSS, «сервер падает».
  Лечение: `allow_reuse_address = False` + `start_dev_5500.ps1` убивает всё на порту.
- Залипший кеш `style.css?v=6` (пустой/битый файл) → меню поверх hero, Times New Roman.
  Лечение: в HTML подставляется `?v=` **только у CSS/JS**, токен от старта сервера.
  Не ставить новый `?v=` на картинки при каждом F5 — главная качает мегабайты и зависает.
- `Connection: close` + лог каждого GET в консоль + лимит 8 потоков → вечная загрузка.
  Лечение: keep-alive, gzip HTML/CSS/JS, кеш картинок/шрифтов/CSS/JS, тихий лог.
- Chrome рвёт сокеты (`WinError 10054`) — нельзя давать traceback, иначе белый экран.
  Лечение: глотать reset в `handle` / `handle_error`.
